# 网站图标获取与缓存

正式扩展现已接入后台统一获取服务。首页、快速搜索和编辑预览使用同一个加载器；不会从卡片 DOM 猜测站点网址，也不会把自动图标 URL 写入飞书的“备用图标”字段。

## 获取顺序

1. 以页面完整 URL（去掉 hash）和自定义图标 URL 构建缓存键，先读 IndexedDB。
2. 有自定义 URL 时优先读取；失败后进入自动获取。
3. 浏览器 `/_favicon/` 接口已有至少 64px 的图标时直接复用；否则解析网站 HTML、Web Manifest，结合浏览器及根目录常见图标候选，按来源、格式、真实解码尺寸选图。
4. 主要来源没有合格图片时，才使用原有 Google S2 回退。本机、内网地址不会发送到公共图标服务。
5. 失败显示站名首字，页面不保留破图；显式的文字、Emoji、图标字体和已有 data 图片继续兼容。

下载通过 Service Worker 执行，不带 Cookie、Referer，不执行网站脚本。HTML 和单张图片均限制为 512 KiB，单次下载超时 2.5 秒，图片解码有独立超时。一次发现主候选最多 8 个，同时最多处理 3 个站点、6 个下载；不同页面对同一缓存键的请求在后台合并。

## 存储与失效

数据库 `chromeNavSiteIcons`、对象仓库 `icons` 存放图片 Blob、来源、尺寸、评分和时间。最多 20 MiB、1000 条，在写事务中按最近访问淘汰。不会把用户图标打进扩展包，也不会把二进制写入飞书或 chrome.storage.sync。

- 成功图标 30 天后可后台更新；先展示旧图，更新失败继续保留。
- 失败记录持久保留 1 小时，避免新标签页和搜索反复重试；旧图更新失败也进入冷却。
- 编辑网站时点击“重新获取网站图标”绕过冷却并刷新，成功后更新当前页面已显示的同站图标。
- 图标 URL 留空表示自动获取。自定义地址保留优先级；旧数据没有 customIcon 字段时识别系统生成的 Google S2 地址，避免误判成手动图标。
- 设置页“清除缓存”和“重置”同时清理图标缓存，清理前已开始的下载不会重新填回缓存。

## 文件与权限

`js/modules/site-icon-core.js` 是纯逻辑；`site-icon-cache.js` 负责 IndexedDB；`site-icon-service.js` 负责后台获取；`site-logo-manager.js` 负责前台显示与 Blob URL 释放；`js/site-icon-offscreen.html` 和配套 JS 负责 DOMParser 与实际图片解码。

新增 `favicon`、`offscreen` 权限，HTTP/HTTPS 主机权限用于读取用户保存的站点、声明图标和自定义图片；最低 Chrome 版本为 109。普通网页和 content script 不能调用本扩展图标代理。更新后需要在扩展管理页重新加载扩展，使新权限与 Service Worker 生效。

## 验证

`tests/site-icons.test.js` 覆盖 URL 与缓存键、自动/手动区分、Manifest 解析、IndexedDB 重建、容量淘汰、合并请求、下载限流、失败冷却、刷新保留旧图、清缓存与下载竞态、图片校验、渲染竞态和代理来源检查。

全量测试 149 项通过，UTF-8、JavaScript 语法及扩展脚本引用检查通过。

真实浏览器验证使用独立资料目录与本机 HTTP 测试站点，验证 offscreen 解析、相对路径、128px 图标、Blob 展示、页面/浏览器重启后的缓存读取，以及首页、搜索和编辑预览共用缓存。测试站点首次收到 7 次获取请求，页面刷新、搜索、预览和完整浏览器重启后仍为 7 次；站点返回 503 时手动刷新提示“刷新失败，继续使用缓存图标”，原图继续显示。测试不读取或修改用户实际浏览器数据。
