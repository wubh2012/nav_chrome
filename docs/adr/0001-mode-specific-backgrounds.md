# ADR-0001：按明暗模式保存独立背景

- 状态：已接受
- 日期：2026-08-07

## 背景

扩展原先只保存一套全局背景配置和一张本地上传图。用户切换浅色、深色模式时，界面颜色会变化，但自定义背景不会变化。“主题”一词同时指皮肤和明暗模式，也容易造成配置含义不清。

## 决策

背景配置升级为两个全局档案：`light` 和 `dark`。每个档案独立保存背景模式、图片 URL、图片适配、遮罩、模糊和更新时间；本地上传图也使用对应的独立 IndexedDB 记录。

石墨、霓虹、奶油属于皮肤，只决定界面调色板，不增加背景档案。切换皮肤不换图，切换明暗模式才加载对应背景。自定义图片优先于默认 Art Deco 背景；目标图片加载失败时，只把目标档案恢复为默认背景。

设置页使用“浅色背景 / 深色背景”标签分别编辑两套档案。恢复默认只处理当前标签，重置所有设置才清除两套档案。

## 数据迁移

旧 `chromeNav_backgroundSettings` 单对象在首次读取时迁移为版本 2 结构。旧配置归入升级时 `chromeNav_theme.mode` 指向的明暗模式，另一模式使用默认配置。

如果旧配置使用本地上传图，`currentBackground` 会先复制到目标模式的上传图记录；目标记录写入成功后才删除旧记录。迁移失败时保留旧配置，以便下次重试。

## 结果

- 用户可以为浅色、深色模式分别选择默认背景、上传图或图片 URL。
- 只维护两套背景，不因三套皮肤扩展成六套，设置成本和本地存储占用保持可控。
- 主题管理器通过事件通知背景管理器，两个模块不直接互相持有渲染状态。
- 快速连续切换通过请求版本校验忽略过期图片加载结果。
